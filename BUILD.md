# Build Documentation

English | [中文](BUILD.zh-CN.md)

## Requirements

- Windows 10 / 11
- .NET 8 SDK (used only for compiling; the output targets .NET Framework 4.8, with reference assemblies provided by the NuGet package `Microsoft.NETFramework.ReferenceAssemblies` — no .NET Framework Developer Pack needed)

Install the SDK (either option):

```bash
winget install Microsoft.DotNet.SDK.8
```

Or download from the official site: https://dotnet.microsoft.com/download/dotnet/8.0

Verify the installation:

```bash
dotnet --version   # should print 8.x
```

## Restore & Build

```bash
dotnet restore   # first run needs network access to fetch the reference assemblies package; offline builds work afterwards
dotnet build -c Release
```

The project has zero third-party runtime dependencies (only the .NET Framework 4.8 and WPF bundled with Windows).

## Output (portable)

Build output:

```
src/OpenWithMgt/bin/Release/net48/OpenWithMgt.exe
```

This exe is only a few dozen KB, single-file and install-free: Windows 10/11 ships with .NET Framework 4.8, so you can copy it to any folder on any Win10/11 machine and double-click to run (UAC elevation is requested at startup, see below). No runtime installation is needed.

## Run (development)

```bash
dotnet run --project src/OpenWithMgt
```

Note: the app manifest declares `requireAdministrator`, so run it from an elevated terminal, otherwise the process will fail to start.

## Regenerating the App Icon

The icon is generated by `tools/IconGen` (WPF vector drawing → multi-size PNG frames packed into a .ico; the tool itself targets .NET 8 and does not affect the main app's output):

```bash
# run from the repository root
dotnet run --project tools/IconGen
```

It outputs `assets/app.ico` (multi-size, 16–256) and `assets/app.png` (256px preview).
To change the icon design, edit the `DrawIcon` method in `tools/IconGen/Program.cs` and re-run.

## Release

Releases are published by GitHub Actions and are triggered **only by pushing a `v*` tag to GitHub (origin)** — regular commits and pushes never publish anything. The process:

1. Bump `<Version>` in `src/OpenWithMgt/OpenWithMgt.csproj` (e.g. `1.1.0`), commit, and verify with `dotnet build -c Release`
2. Tag and push (push to origin only, not gitee):

   ```bash
   git tag v1.1.0
   git push origin main --tags
   ```

3. GitHub Actions (`.github/workflows/release.yml`) verifies that the tag version matches the csproj version, builds the Release configuration, and creates a release on the [Releases page](https://github.com/minichen2000/OpenWithMgt/releases) with `OpenWithMgt-v<version>.zip` (containing the exe and the README) plus the raw `OpenWithMgt.exe`
4. After publishing, confirm on the Releases page that the artifacts download correctly
